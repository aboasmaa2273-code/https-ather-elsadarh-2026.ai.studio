# خطة الاختبار السلوكي لمنصة أَثَر — بيئة تجريبية معزولة

## الغرض والنطاق

هذه الخطة مخصصة لاختبار نسخة التطوير على مشروع Google Apps Script وجدول بيانات تجريبيين منفصلين تمامًا عن مشروع المدرسة وبياناتها. نجاح GitHub Actions أو فحص البناء لا يُعد تنفيذًا لهذه الاختبارات.

**حظر صريح:** لا تستخدم مشروع Apps Script الحي، ولا جدول بيانات المدرسة، ولا تنسخ بيانات حقيقية أو كلمات مرور حقيقية إلى البيئة التجريبية. لا تنفذ أي اختبار قبل التحقق يدويًا من أن المشروع والجدول جديدان ومعزولان، والحصول على موافقة مستقلة لتشغيل التهيئة التجريبية.

## شروط البدء الآمن

- [ ] إنشاء مشروع Apps Script تجريبي جديد، مستقل عن مشروع المدرسة.
- [ ] إنشاء Google Sheet تجريبي جديد وفارغ، لا يحتوي بيانات المدرسة.
- [ ] التحقق من معرّف الجدول التجريبي من عنوانه، وعدم استخدام معرّف الجدول الحي.
- [ ] في Script Properties للمشروع التجريبي فقط، ضبط `ATHAR_DATABASE_SPREADSHEET_ID` على معرّف الجدول التجريبي.
- [ ] مراجعة اسم المشروع ومعرّف الجدول مرة أخرى قبل أي تهيئة.
- [ ] بعد موافقة مستقلة على هذه الخطوة، تهيئة قاعدة البيانات التجريبية فقط، ثم نشر نسخة اختبار محدودة الوصول.
- [ ] استخدام أسماء وهمية وأرقام وظيفية وكلمات مرور تجريبية فقط.

إذا لم تُضبط الخاصية، يجب أن تفشل وظائف قاعدة البيانات برسالة واضحة، وألا تفتح أي جدول افتراضي أو جدول المدرسة.

## حسابات الاختبار الوهمية

أنشئ حسابات اختبار منفصلة بالأدوار التالية، مع ربط حساب المعلم بسجل معلم تجريبي نشط:

- مسؤول منصة تجريبي.
- مدير مدرسة تجريبي.
- نائب مدير تجريبي.
- مقيّم تجريبي (أ).
- مقيّم تجريبي (ب).
- معلم تجريبي (أ).
- معلم تجريبي (ب).

لا تستخدم البريد أو اسم المستخدم أو كلمة المرور الخاصة بأي شخص حقيقي.

## حالات الاختبار

| الرمز | السيناريو | النتيجة المتوقعة |
|---|---|---|
| DB-01 | تشغيل فحص الصحة دون ضبط معرّف الجدول في مشروع تجريبي منفصل | `databaseReady=false` ورسالة توضح غياب الخاصية، دون إنشاء أو فتح جدول تلقائي |
| AUTH-01 | دخول باسم مستخدم وكلمة مرور صحيحين | نجاح الدخول وإصدار جلسة صالحة |
| AUTH-02 | دخول بكلمة مرور خاطئة | رفض الدخول وعدم إصدار جلسة |
| AUTH-03 | تكرار اسم المستخدم في سجلين تجريبيين | رفض الدخول بسبب الالتباس وعدم اختيار سجل عشوائي |
| AUTH-04 | تعطيل حساب ثم استخدام جلسته السابقة | رفض الطلب المحمي مباشرة بعد التعطيل |
| AUTH-05 | انتهاء صلاحية الجلسة أو تغيير توقيعها | رفض الطلب المحمي |
| AUTH-06 | خمس محاولات فاشلة متتالية | تطبيق التقييد المؤقت وفق السلوك المبرمج |
| ROLE-01 | المعلم (أ) يطلب بيانات المعلم (ب) | لا تظهر بيانات المعلم (ب) |
| ROLE-02 | المقيّم (أ) يحاول تعديل زيارة يملكها المقيّم (ب) | رفض العملية دون تغيير السجل |
| ROLE-03 | المقيّم يحاول اعتماد تقرير | رفض العملية إذا كانت صلاحية الاعتماد إدارية فقط |
| ROLE-04 | مدير المدرسة يحاول تعديل حساب مسؤول منصة أو تعطيله | رفض العملية |
| VISIT-01 | إنشاء زيارة تجريبية بمؤشرات صحيحة | حفظ الزيارة والتفاصيل المرتبطة بها مرة واحدة |
| VISIT-02 | إرسال مؤشرات مكررة أو دون معرّفات | رفض الحفظ دون ترك سجلات جزئية |
| VISIT-03 | تعديل زيارة معتمدة أو مؤرشفة من دور غير مخول | رفض التعديل |
| VISIT-04 | محاولة تعديل زيارة تخص مدرسة تجريبية أخرى | رفض العملية |
| PLAN-01 | إنشاء خطة تطوير للمعلم التجريبي | حفظ الخطة وربطها بالمدرسة والمالك الصحيحين |
| PLAN-02 | إضافة متابعة للخطة | إضافة المتابعة وتحديث حالة الخطة وتاريخها بصورة متسقة |
| PLAN-03 | محاكاة فشل أثناء حفظ المتابعة | التحقق من عدم حذف سجل غير مرتبط، ومن سلامة الاستعادة أو ظهور تحذير واضح عند تعذرها |
| ARCH-01 | أرشفة زيارة تجريبية من حساب إداري مخول | تتغير حالة الأرشفة مع بقاء السجل |
| ARCH-02 | استعادة الزيارة المؤرشفة | تعود الزيارة وفق الصلاحيات دون إنشاء نسخة مكررة |
| ARCH-03 | محاولة حذف تقرير زيارة نهائيًا | يرفض الخادم الحذف النهائي |
| ACCOUNT-01 | تحديث كلمة مرور الحساب التجريبي | حفظ الملح والتجزئة الجديدين ونجاح الدخول بكلمة المرور الجديدة |
| ACCOUNT-02 | طلبان متزامنان لتحديث بيانات الحساب | لا تتلف الأعمدة أو البيانات، ويُحسم التحديث بصورة متسقة |
| ACCOUNT-03 | إعادة تفعيل حساب معلم مرتبط بسجل معلم غير نشط أو ملتبس | رفض إعادة التفعيل مع توضيح السبب |

## توثيق نتيجة كل اختبار

لكل حالة، سجّل: الرمز، التاريخ والوقت، الدور المستخدم، المدخلات الوهمية، النتيجة الفعلية، النتيجة المتوقعة، وصورة شاشة منزوعة أي أسرار أو رموز جلسات. لا تسجل كلمات المرور أو رموز الجلسات أو مفاتيح التوقيع.

## معيار اجتياز المرحلة

- نجاح جميع حالات العزل والصلاحيات ومنع الوصول غير المصرح به.
- عدم فقدان أو تكرار أي سجل في اختبارات الحفظ والأرشفة والاستعادة.
- عدم وجود أخطاء غير معالجة في سجل تنفيذ Apps Script.
- توثيق أي فشل وإصلاحه وإعادة الاختبار.
- لا يُعتمد النشر الرسمي بمجرد نجاح الاختبارات البنيوية؛ يلزم اعتماد نتائج الاختبار التجريبي وموافقة مستقلة على الدمج والنشر.

## حدود هذه الخطة

إضافة هذه الخطة إلى المستودع لا تنشئ مشروع Google تجريبيًا ولا تشغّل Apps Script ولا تختبر قاعدة بيانات فعلية. جميع الاختبارات أعلاه ما زالت غير منفذة إلى أن تُنشأ البيئة المعزولة وتُمنح الموافقات اللازمة.
