# دليل تحديث ونشر ملفات Google Apps Script لمنصة «أَثَر»

هذا المجلد هو المصدر المعتمد لملفات خلفية منصة «أَثَر» على فرع التطوير `ather-development`.

## الملفات

- `Code.gs`: منطق الخادم والصلاحيات والتقارير وإدارة البيانات.
- `Bridge.html`: جسر الاتصال الآمن بين واجهة GitHub Pages وخادم Apps Script.
- `Index.html`: صفحة تطبيق الويب.
- `Styles.html`: تنسيقات تطبيق الويب.
- `Client.html`: كود العميل داخل Apps Script.
- `appsscript.json`: إعدادات المشروع والنطاقات الزمنية والصلاحيات.

## تنبيه حماية البيانات

**لا تشغّل `initializeDatabase_()` عند تحديث نسخة قائمة.** هذه الدالة مخصصة لتهيئة قاعدة بيانات، وليست خطوة تحديث اعتيادية. وهي الآن دالة داخلية لا تُستدعى من واجهة الويب. لا تنشئ جدول بيانات جديدًا، ولا تغيّر خاصية `ATHAR_DATABASE_SPREADSHEET_ID`، ولا تحذف أوراق العمل أو محتوياتها.

ملف `Code.gs` مضبوط ليرتبط بقاعدة البيانات المدرسية الموجودة إذا لم تكن خاصية المعرّف مضبوطة في خصائص المشروع. يجب إبقاء المعرّف الحالي كما هو.

دوال إعداد الحسابات الحساسة `migrateUserPasswordColumns_()` و`setUserPassword_()` مخصصة للتشغيل الإداري اليدوي من محرر Apps Script فقط، وليست إجراءات متاحة من طلبات الويب. لا تغيّر كلمات مرور الحسابات أو أعمدتها أثناء تحديث الواجهة.

## طريقة التحديث الآمن لمشروع Apps Script الموجود

1. افتح مشروع Apps Script المرتبط حاليًا بمنصة «أَثَر»، وليس مشروعًا جديدًا.
2. تأكد من أنك داخل حساب Google المالك للمشروع.
3. حدّث محتوى الملفات الموجودة فقط من النسخة المعتمدة في هذا المستودع:
   - استبدل محتوى `Code.gs` بمحتوى `gas/Code.gs`.
   - حدّث ملفات HTML الموجودة إذا تغيّرت في التحديث المعتمد. لا تحذف `Bridge.html`.
   - لا تغيّر إعدادات المشروع أو خصائصه لمجرد إتمام التحديث.
4. احفظ المشروع وانتظر اكتمال الحفظ.
5. افتح **Deploy → Manage deployments**.
6. اختر نشر تطبيق الويب الحالي واضغط **Edit**.
7. اختر **New version** ثم **Deploy**. لا تنشئ نشرًا جديدًا إذا كان المطلوب الحفاظ على رابط التطبيق الحالي.
8. تحقق من رابط `/exec` الحالي، ثم اختبر الاتصال من صفحة المنصة باستخدام فحص الاتصال فقط.

## اختبارات ما بعد التحديث

- افتح الصفحة الرئيسية وتأكد من تحميلها.
- اختبر فحص الاتصال `health` من مركز الربط.
- تحقق من تسجيل الدخول والصلاحيات.
- اختبر قراءة البيانات دون تعديلها.
- اختبر الوظائف الجديدة في حساب تجريبي مناسب قبل استخدامها مع بيانات فعلية.

لا تستخدم إرسال بريد أو فتح واتساب كتجربة على معلم حقيقي دون موافقته.

## ما الذي يفعله GitHub Actions؟

ملف سير العمل `.github/workflows/validate-gas-development.yml` يفحص صياغة JavaScript في `Code.gs`، ويتحقق من صحة ملف JSON ووجود الملفات والإجراءات الأساسية، ثم يحزم ملفات Apps Script في ملف ZIP قابل للتنزيل من صفحة تشغيل GitHub Actions.

**هذا الفحص لا ينشر إلى Google Apps Script ولا يثبت نجاح الاتصال بالخادم الحي.** النشر إلى Google يظل خطوة مستقلة تتطلب صلاحية الدخول إلى مشروع Apps Script.
